## 2026-06-04 - Visual Smoke Capture

Status: visual-smoke-capture checkpoint

- Added `script/zed-terminal-visual-smoke.ps1` as a repeatable Windows release smoke entry point for the standalone terminal.
- The script launches the real built `zed-terminal.exe` with isolated per-run config/data roots under `target\zed-terminal-visual-smoke`.
- The smoke uses the normal startup command path to run a deterministic PowerShell probe inside the terminal, waits for a probe readiness marker, and then captures the app's visible top-level window.
- The capture path uses Windows `PrintWindow(PW_RENDERFULLCONTENT)` instead of desktop `CopyFromScreen`, because `CopyFromScreen` can falsely capture the desktop background for the GPUI/WGPU window.
- The script writes a PNG screenshot plus process/window/capture statistics and fails if the process exits early, no window appears, the probe does not run, `PrintWindow` fails, or the screenshot is blank/nearly blank.
- Kept this as a verification-tooling iteration only; no terminal renderer, input, PTY, startup layout, keymap, or product UI behavior was changed.
- This closes the previous ad hoc visual-check gap for release checkpoints, while leaving pixel-baseline comparison against official Zed terminal screenshots as future work.
