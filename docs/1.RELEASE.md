# Zed Terminal Release Notes

This file records major standalone `zed_terminal` milestones and release-capable checkpoints.

## 2026-06-04 - Independent Product Paths and Keymap

Status: product-paths checkpoint

- Added independent `Zed Terminal` config/data/log roots for the standalone app instead of sharing normal Zed paths by default.
- Added `--paths`, `--user-data-dir <directory>`, and `--config-dir <directory>` for inspecting and overriding product paths.
- Created terminal-specific `settings.json`, `global_settings.json`, and `keymap.json` files before settings/keymap watches start.
- Added `assets/keymaps/zed-terminal.json` as the standalone default keymap, loaded through Zed's `settings::KeymapFile` path with user keymap hot reload.
- Added an app menu action for opening the terminal-specific keymap file.
- Kept `ctrl-j` unbound in the standalone keymap and added a terminal mapping regression test so it continues to reach the terminal as LF input.
- Extended `paths` with custom config/data setters needed by the standalone app while keeping normal Zed defaults unchanged.

Verification:

- `cargo +stable fmt --package zed_terminal --package paths --package terminal`
- `cargo +stable test -p zed_terminal --bin zed-terminal`
- `cargo +stable test -p terminal test_ctrl_j_line_ending`
- `cargo +stable check -p zed_terminal`
- `cargo +stable build -p zed_terminal --bin zed-terminal`
- `target\debug\zed-terminal.exe --help`
- `target\debug\zed-terminal.exe --paths --user-data-dir <temp-dir>`

## 2026-06-04 - Startup Command CLI

Status: startup-command checkpoint

- Added startup command support for `zed-terminal -- <command> [args...]`.
- Supported combining startup directories and startup commands with `zed-terminal <directory> -- <command> [args...]` and `zed-terminal -d <directory> -- <command> [args...]`.
- Accepted command arguments that begin with `-` after the `--` separator.
- Mapped startup commands to `task::SpawnInTerminal` and opened them through `Project::create_terminal_task` so Zed's existing shell wrapping, environment handling, task summary, and terminal rendering remain authoritative.
- Kept the implementation scoped to `crates/zed_terminal` plus docs and avoided changes to the shared terminal renderer.

Verification:

- `cargo +stable test -p zed_terminal --bin zed-terminal`
- `cargo +stable check -p zed_terminal`
- `cargo +stable build -p zed_terminal --bin zed-terminal`
- `target\debug\zed-terminal.exe --help`
- `target\debug\zed-terminal.exe --startingDirectory .\this-directory-should-not-exist`

## 2026-06-04 - Startup Directory CLI

Status: startup-directory checkpoint

- Added startup working directory support for `zed-terminal`.
- Supported `-d`, `--working-directory`, `--cwd`, `--starting-directory`, `--startingDirectory`, and a positional directory argument.
- Canonicalized and validated the requested directory before GPUI startup so launch failures are explicit.
- Passed the resolved directory to the first terminal shell and the standalone New Tab action used by `ctrl-shift-t` and the Shell menu.
- Registered the resolved directory as the workspace worktree so native Zed terminal affordances can still use the same project-root default through existing Zed terminal logic.
- Followed Microsoft Learn's Windows Terminal `-d` / `--startingDirectory` convention while keeping the implementation isolated to `crates/zed_terminal`.
