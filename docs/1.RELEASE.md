# Zed Terminal Release Notes

This file records major standalone `zed_terminal` milestones and release-capable checkpoints.

## 2026-06-05 - Active Keymap Binding Detail Discovery

Status: active-keymap-binding-detail-discovery checkpoint

- Added `zed-terminal --describe-active-keymap-binding <KEYSTROKES>` with `--describe-active-keymap-binding-format text|json` to inspect the bindings that are active after applying user `keymap.json` overrides.
- Added `--describe-active-keymap-binding-context <CONTEXT>` for focused context diagnostics; with no explicit context the command uses the standalone terminal dispatch context (`os=<current>` plus `Terminal`) to match the normal terminal surface.
- The active binding path builds a real GPUI `Keymap` from the bundled standalone default keymap plus the active user keymap and queries it with `Keymap::bindings_for_input`, preserving user priority, unbinds, pending prefixes, context depth, and source metadata instead of approximating conflicts with string matching.
- JSON output reports `status`, bundled default keymap source, active user keymap path/source, requested and parsed keystrokes, contexts, pending state, match count, and each active match's source, display keystrokes, action, namespace, context, and serialized input.
- The command is parsed through the narrow early keymap discovery path with the same path-only isolation as keymap schema/action/default-binding discovery; it does not load startup config, and it never prints user keymap comments or raw file contents.
- Extended help discoverability, Rust parser/formatter coverage, and the release gate to validate user-overridden NewTerminalTab and Terminal Paste active binding contracts.
- Kept this as shortcut settings/diagnostic tooling only; no terminal renderer, input handling, PTY setup, shell/task creation, startup layout semantics, bundled key bindings, product UI style, or visual styling was changed.
